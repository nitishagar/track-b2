otps — Timing-Correlation Diff Engine

Explain why timing slack changed between two chip-design runs.

Pre- vs post-route, corner A vs B, flow v1 vs ported v2 — otps aligns the "same" timing paths across two reports and attributes the slack delta stage by stage, in seconds, offline. See the OTPS format spec and how the pipeline works.

Quickstart

cargo build --locked
cargo run -q -p otps-cli -- diff fixtures/base.rpt fixtures/route.rpt --corner sky130hd
cargo run -q -p otps-cli -- diff fixtures/base.rpt fixtures/route.rpt --fail-on-regression-ps 50

The first command builds the workspace. The second diffs the synthetic pre/post-route fixture pair (plain text or .gz accepted). The third is the CI gate: it exits 2 if any matched path regresses more than 50 ps. Full flag reference is on the adopters page; machine-readable output via --format json.

Sample output

otps diff (schema 0.1.0)
base: 6 paths  new: 7 paths  matched: 6 (unmatched base 0, new 1)
match rate: 85.7%
worst slack delta: -0.102 ns
worst residual: 0.000000 ns
top regressions:
  -0.102 ns  NetDelay  u_core/ff1 -> u_core/ff2  (explained 100%)
  ...
clusters:
  NetDelay x3 [u_core]: total -0.202 ns
  ...

Every report prints its match rate and unexplained residual: a large residual means "uncertain", never "clean". Up to 5 worst regressions and the cluster roll-up (dominant component + hierarchy prefix) are shown.

Ground rules

  • No telemetry. No network. The CLI makes zero network calls; --offline is the only mode.
  • Apache-2.0. Free to use, modify, and redistribute.
  • Not a signoff tool. This is signoff-adjacent triage: it narrows 2,000 miscorrelated endpoints to a handful of root causes, but it never certifies timing.
Legal guardrail: public fixtures and demos use only OpenSTA/OpenROAD-style data. This project never links OpenSTA (GPL-3.0) and never publishes commercial-tool outputs or tool-vs-tool comparisons. Details on the adopters page.
