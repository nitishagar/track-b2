otps — Timing-Correlation Diff Engine
Home Format Architecture Adopters Roadmap

Path-level timing correlation across runs, corners, and flow revisions.

When slack for the "same" path differs between two analyses — pre- vs post-route, corner A vs B, flow v1 vs a ported v2 — otps aligns the paths and decomposes the delta per stage into cell delay, net delay, and required-time movement. Miscorrelation triage starts from a ranked, attributed list instead of two text reports. Spec: OTPS format · pipeline: architecture · rollout: adopters.

What you get

  • Path matching with a reported match rate. Exact key (startpoint, endpoint, clocks, check type), then through-pin Jaccard fallback for renamed or ECO-touched paths. Unmatched paths are listed, and the match rate is printed on every report.
  • Stage-level attribution. Each matched pair is decomposed as Δslack = Δrequired − Δarrival, with Δarrival split into cell vs net per stage. The unexplained residual is always printed: a large residual means "uncertain", never "clean".
  • Root-cause clustering. Paths group by dominant component and hierarchy prefix, so thousands of moved endpoints collapse to a handful of causes. Ordering is deterministic across runs.
  • CI-ready output. Human-readable summary or --format json; --fail-on-regression-ps N exits 2 when any matched path regresses more than N ps.

Fits your flow

  • Single static binary (cargo build --release); no root, no runtime, no installer. Runs on air-gapped farms.
  • Zero network calls and zero telemetry. --offline is the only mode; report files never leave the machine.
  • Reads plain text or .gz reports plus JSON exporter dumps; non-finite numbers and malformed lines fail loudly with line numbers.
  • Apache-2.0. No OpenSTA linking (GPL-3.0); public fixtures and demos use only OpenSTA/OpenROAD-style data.

Scope in v0.1.0

InputsOTPS text v0.1 (OpenSTA report_checks subset), JSON dumps, .gz
ChecksSetup/max and hold/min; required, arrival, CRPR, uncertainty carried per path
OutputsText summary, JSON, exit codes 0 (ok) / 1 (error) / 2 (gate failed)
Not in scopeSignoff. This is signoff-adjacent triage: it narrows the suspect list, it never certifies timing

Accuracy basis

  • Self-consistency invariants checked per path (Σincrements = arrival, required − arrival = slack).
  • Perturbation-tested: injected net-delay growth and required-time shifts on the fixture pair are attributed to the right component at 100% explained.
  • 19 tests plus four CI gates (build, clippy -D warnings, fmt --check, test) on every push.

Quickstart

cargo build --locked
cargo run -q -p otps-cli -- diff fixtures/base.rpt fixtures/route.rpt --corner sky130hd
cargo run -q -p otps-cli -- diff fixtures/base.rpt fixtures/route.rpt --fail-on-regression-ps 50

The first command builds the workspace. The second diffs the synthetic pre/post-route fixture pair. The third is the CI gate: it exits 2 because the worst matched regression (−102 ps) exceeds the 50 ps budget. Full flag reference is on the adopters page.
