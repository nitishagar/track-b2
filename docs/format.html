Supported inputs (schema 0.2.0)

otps ingests real STA reports — no exporter required for the OpenSTA flow. All delays are in nanoseconds. The CLI auto-sniffs each input (text vs JSON), reads .gz-compressed inputs transparently, and accepts - for stdin. The three layouts below all land in the same Open Timing Path Schema (Run → Path → Point). Identity includes the report flavor, so diff same-format reports: a text-vs-JSON cross-format diff of the same design will not match, by design.

Real report_checks text (primary)

Plain report_checks output: Startpoint / Endpoint headers, Arrival / Required spans with Time and Delay columns, and a slack footer. Time-delta spans are canonical (the Delay column cross-checks them); folded clock <name> spans parse with their available edge split off as the clock edge time. Blocks the schema cannot represent — (Path is unconstrained) paths, path_delay and nonzero-path_margin summaries — are skipped and counted on stderr, never silent. Cap/slew/variation columns, generated-clock source paths, and short/end/summary aggregates are rejected with reasons (future work).

Native STA JSON

Native tool JSON path dumps stream through the same pipeline. Setup margin is negated at ingest (the schema stores the required-offset contribution), output_delay routes to external delay, and CRPR parity holds on both sides. Fields with no JSON key (uncertainty) stay unknown and are listed, not zeroed.

Legacy OTPS text v0.2

A fixed-order path block used by the shipped fixtures and the JSON exporter round-trip. (v0.1 layouts are rejected with a migration pointer.) Each path is a fixed-order header, a Points: line, one or more point lines, and a terminating End line. Blank lines and lines starting with # are ignored:

Startpoint: <start pin/instance>
Endpoint: <end pin/instance>
Launch clock: <clock>
Capture clock: <clock>
Launch edge: rise|fall|unknown
Capture edge: rise|fall|unknown
Group: <path group, may be empty>
Check: setup|max|hold|min
Slack: <ns, per-check sign>
Required: <ns>
Arrival: <ns>
Launch edge time: <ns>
Launch srclat: <ns>
Launch net: <ns>
Capture edge time: <ns>
Capture srclat: <ns>
Capture net: <ns>
Uncertainty: <ns>|none
Crpr: <ns>|none
Margin: <ns>|none
External: <ns>|none
Points:
<point line>
...
End

Point line

Point lines use pipe-separated columns followed by space-separated key=value attributes:

<pin> | <cell type> | <net> | cell=<ns> net=<ns> slew=<ns> cap=<fF> fanout=<int> [derate=<mult>] [sigma=<ns>] [si=<ns>] [trans=<rise|fall>] [arrival=<ns>] [split=<yes|no>]
AttributeMeaningRequired?
cellCell (gate) incremental delay, nsNo (default 0)
netNet (wire) incremental delay, nsNo (default 0)
slewTransition slew, nsNo
capLoad capacitance, fFNo
fanoutFanout count (integer)No
derateApplied derate multiplierOptional
sigmaPOCV/LVF sigma, nsOptional
siSI-induced delta delay, nsOptional
transTransition marker (rise/fall)Optional
arrivalCumulative arrival at this point, nsOptional
splitAvailable-edge split marker for folded clock spans (yes/no)Optional

Only the pin column is required; cell/net columns may be empty. Unknown attribute keys are a parse error (reported with a 1-based line number).

Self-consistency invariants

Every path must satisfy (within 1e-6 ns, checked by diff before matching):

  • sum(point cell + net increments) == arrival
  • setup: required - arrival == slack; hold: arrival - required == slack
  • required-side parts reconcile with the header required time

A violation is reported as an error naming the endpoint — it flags a parser or exporter bug, never a timing verdict.
