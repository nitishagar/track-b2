Who it is for

  • STA / timing-closure engineers — "tell me in 5 minutes which of these 2,000 miscorrelated endpoints share a root cause, and which component (net delay, clock latency, derate) drives it."
  • PD / CAD leads — gate flow upgrades in CI: fail if path-level slack regresses beyond X ps on any endpoint group.
  • Flow-porting / methodology engineers — prove a ported flow correlates with the old one and quantify residuals per stage.
  • OSS-silicon / academic designers — why did timing change between OpenROAD-flow-scripts versions or PDK revisions?

It runs anywhere Rust builds, needs no licenses, no network, and no root — drop two report files on it. Start with the quickstart on the home page.

CI gate recipe

Fail the build (exit code 2) when any matched path regresses more than the budget, or any added path violates beyond the budget absolute. --fail-on-regression-ps N trips when the worst matched slack delta is worse than −N ps, or the unmatched-new WNS is worse than −N ps:

# Shell / Jenkins / generic CI
cargo run -q -p otps-cli -- diff base.rpt route.rpt --fail-on-regression-ps 50
# exit 0 = within budget, exit 2 = gate tripped, exit 1 = input error
# GitHub Actions
- name: Timing regression gate
  run: |
    cargo run -q -p otps-cli -- diff base.rpt route.rpt \
      --base-corner ${{ matrix.corner }} --format json --fail-on-regression-ps 50 | tee diff.json

Use --format json for machine-readable output (counts, match/fuzzy/combined rates, worst deltas, unmatched-new WNS, both runs with mismatches, attributions, clusters) and --base-corner / --new-corner / --base-pdk / … to label each side. Tip: gate on a budget your flow genuinely holds (start loose, e.g. 100 ps, and tighten once the attribution output is trusted), and always read the printed match rate and residual before treating a green gate as "clean". Flag details are in the CLI reference.

EULA guardrails

Non-negotiable. These rules protect the project and its users from EDA license exposure.
  • OpenSTA-only public data. Public fixtures, demos, and docs use only OpenSTA/OpenROAD-style data. Never commit reports generated by commercial tools.
  • Never link OpenSTA. OpenSTA is GPL-3.0; this Apache-2.0 codebase must never link it. Subprocess invocation for local demos only.
  • No commercial comparisons. Never publish commercial-tool outputs or tool-vs-tool comparisons — vendor EULAs explicitly bar disclosing benchmark/comparison results to third parties. Internal use of the tool by licensed engineers on their own results is a separate, low-risk matter.

CONTRIBUTING legal note

Before contributing samples, fixtures, or exporter scripts:

  • Contribute timing samples from OpenSTA only, unless you have your employer's explicit legal sign-off.
  • Even anonymized commercial-tool outputs may count as licensor "results" — when in doubt, do not attach them; describe the shape of the data instead.
  • Exporter scripts must use documented tool commands in your own licensed session, written in your own words — never copy vendor docs or scripts verbatim.
  • All contributions are under the repo's Apache-2.0 license; confirm you have the right (employer clearance, no IP encumbrance) to contribute.
