Architecture

Four pipeline stages turn two report files into an explained, clustered diff. See the format spec for the input schema.

report files ──▶ 1. Parse ──▶ 2. Match ──▶ 3. Attribute ──▶ 4. Cluster ──▶ text / JSON

1. Parse

parse_text reads the OTPS text format v0.1 (an OpenSTA report_checks subset) with a hand-rolled, allocation-light line parser — no regex — so multi-GB reports stay I/O-bound. parse_json imports JSON dumps produced by in-tool exporter scripts. The CLI auto-selects by extension: .gz inputs are gunzipped transparently, and .json / .json.gz inputs take the JSON path. Run identity (--tool, --tool-version, --corner, --mode, --pdk, --flow-hash) is attached at parse time; both reports in a diff share one run record in the current CLI. Parsed paths are validated against the self-consistency invariants before any matching happens.

2. Match

match_paths aligns the "same" path across the two runs:

  1. Exact key: (startpoint, endpoint, launch clock, capture clock, check type).
  2. Fuzzy fallback: Jaccard similarity over through-pin sets (threshold 0.5) for renamed or ECO-touched paths. Fuzzy matches are counted and reported explicitly.

The match rate (matches / max(base, new)) plus unmatched-base and unmatched-new counts print on every report.

3. Attribute

attribute explains each matched pair. Since slack = required − arrival:

Δslack = Δrequired − Δarrival,   Δarrival = Σcell Δ + Σnet Δ

Stage deltas pair points by pin name; unpaired stages count in full on their own side. Each attribution carries the slack/cell/net/data/required deltas, a residual (unexplained part — near zero when the math is sound), an explained ratio (1 − |residual| / max(|Δslack|, eps)), and a dominant component: CellDelay, NetDelay, Required, or Balanced.

4. Cluster

cluster groups attributions by dominant component plus common hierarchy prefix, so thousands of miscorrelated endpoints collapse to a handful of root-cause lines such as NetDelay x3 [u_core]: total -0.202 ns.

Crate layout

crates/otps-core  schema, parser, matcher, attribution + unit/integration tests
  src/schema.rs        Run → Path → Point model, SCHEMA_VERSION, validate()
  src/parser.rs        OTPS text v0.1 parser + JSON importer
  src/matcher.rs       exact + Jaccard-fallback path matcher
  src/attribution.rs   Δslack attribution + clustering
crates/otps-cli   `otps` binary (parse/diff, text+json, --fail-on gate, .gz)
fixtures/         synthetic pre/post-route pair with injected perturbations
docs/             this guide + GitHub Pages site

CLI reference

otps parse <file> [--tool --tool-version --corner --mode --pdk --flow-hash] [--format text|json]
otps diff <base> <new> [same run flags] [--format text|json] [--fail-on-regression-ps N]
  • parse prints one report's paths (N paths (schema X), then one line per path; JSON prints the full report).
  • diff prints the summary from the home page; JSON prints counts, match rate, worst deltas, all attributions, and clusters.
  • Exit codes: 0 clean, 2 when --fail-on-regression-ps N trips (worst slack delta worse than −N ps), 1 on parse/validation errors.
