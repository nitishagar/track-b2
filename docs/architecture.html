Architecture

Four pipeline stages turn two report files into an explained, clustered diff. See the format spec for the input schema.

report files ──▶ 1. Parse ──▶ 2. Match ──▶ 3. Attribute ──▶ 4. Cluster ──▶ text / JSON

1. Parse

Streaming iterators read the supported inputs with hand-rolled, allocation-light line parsing — no regex — so multi-GB reports stay I/O-bound: PathIter for real OpenSTA report_checks text, JsonPathIter for native STA JSON, plus the legacy OTPS text v0.2 layout. The CLI sniffs each input (.gz gunzipped transparently, - reads stdin) with bounded 1 MiB blocks and an error budget. Each side of a diff gets its own run identity (--base-* flags, --new-* overrides), and field-level run mismatches print on every report. Unrepresentable blocks — unconstrained paths, path_delay / nonzero-path_margin summaries — are counted, never silent. Parsed paths are validated against the self-consistency invariants before any matching happens.

2. Match

match_paths aligns the "same" path across the two runs:

  1. Exact key: (startpoint, endpoint, launch clock, capture clock, edges, group, check type, flavor), FIFO on duplicate keys.
  2. Fuzzy fallback: inverted-index Jaccard over data-pin sets (threshold 0.5, top-128 survivors per path) for renamed or ECO-touched paths. Fuzzy hard-blocks check-type and flavor mismatches and prefers same-clock pairs; matches carry their Jaccard score.

Honesty split: match_rate = exact / max(base, new), with separate fuzzy_rate and combined_rate, plus unmatched-base / unmatched-new counts and the unmatched-new absolute WNS — all printed on every report. Note: identity includes the report flavor, so text-vs-JSON cross-format diffs of the same design do not match by design — diff same-format reports.

3. Attribute

attribute explains each matched pair with per-check slack sign (setup is required − arrival, hold is arrival − required):

Δslack = s·(Δrequired_parts − Δarrival_parts)

Stage deltas pair points by pin name into a top-8 added/removed stage list; unpaired stages count in full on their own side. Each attribution carries the slack/cell/net/data/required deltas, derate and SI sub-splits, a POCV sigma RSS with a 3σ flag, a residual (unexplained part — near zero when the math is sound), an explained ratio (1 − |residual| / max(|Δslack|, eps)), a per-path confidence (High / Reduced with reasons), and a dominant component: CellDelay, NetDelay, LaunchClock, CaptureClock, ClockEdge, Uncertainty, Crpr, CheckMargin, ExternalDelay, Unexplained, or Balanced.

4. Cluster

cluster groups attributions by dominant component plus path group (endpoint hierarchy prefix when the input carries no group), so thousands of miscorrelated endpoints collapse to a handful of root-cause lines such as NetDelay x4 [clk]: total -0.217 ns.

CLI reference

otps parse <file> [--tool --tool-version --corner --mode --pdk --flow-hash] [--format text|json]
otps diff <base> <new> [--base-* run flags] [--new-* overrides] [--format text|json] [--fail-on-regression-ps N]
  • parse prints one report's paths (N paths (schema X), then one line per path; JSON prints the full report).
  • diff prints the summary from the home page; JSON prints counts, match/fuzzy/combined rates, worst deltas, unmatched-new WNS, both runs with mismatches, all attributions, matches, and clusters. New-side run flags fall back per field to the base side, and the unprefixed spellings (--corner, …) still work as base-side aliases.
  • Exit codes: 0 clean, 2 when --fail-on-regression-ps N trips (worst matched slack delta worse than −N ps, or unmatched-new absolute WNS worse than −N ps), 1 on parse/validation errors.
